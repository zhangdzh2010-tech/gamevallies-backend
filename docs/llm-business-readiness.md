# 模型能力与业务路由一致性

旧管理表单用四个复选框同时保存 `verified`、`supports_dialogue`、
`supports_patch_generation` 和 `supports_full_html_rewrite`。新建连接没有标注能力时，
四项仍会被写为 `false`。模型迁移保留这些记录后，运行时把未验证的默认值当成禁止，
而业务绑定只检查启用与区域，允许保存一组完全不可路由的主备模型。

现在由 `contracts/llm/routing-policy.json` 定义业务步骤与能力要求，生成后台和
AI 服务的本地策略。CI 校验生成文件，双方用同一组边界样本验证解释结果。

- 仅精确匹配旧表单的四项全 `false` 默认值时，将能力解释为未知。原始数据库值保留，
  路由快照记录原值和解释方式，不把未知写成已验证支持。
- 单独的能力禁用、`verified=true` 的禁用、有额外字段的记录，以及明确的步骤限制
  均保留。新模型继续用空能力对象表示未知。
- 保存业务绑定前检查整组主备对每个所需步骤的覆盖情况，再进入写入阶段。
  主备可以各自覆盖部分能力；任何步骤均无候选时拒绝保存。
- 后台展示能力路由检查结果，与连通测试分开。运行时失败包含业务环节、步骤及拒绝原因，
  以便区分状态/区域、输出额度和显式能力限制。

这些检查不代替真实作品生成与质量验收。模型输出预算、当前服务可用性和生成质量仍在
实际调用时检查；未改变质量门禁、已有模型身份或业务主备选择。
