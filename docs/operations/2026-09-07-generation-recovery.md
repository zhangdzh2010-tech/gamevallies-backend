## 根因及修复

### 任务生命周期

旧链路：SQL 任务 → BullMQ 分发 → AI 接口返回 202 → `asyncio.create_task` 在内存执行。Redis 仅保存状态；BullMQ 分发结束就完成。发布把队列为空误判成所有工作完成。

新链路：SQL 任务 → BullMQ 分发 → Redis 原子保存完整执行请求 → 返回 202 → 常驻 worker 领取任务执行。租约 90 秒，每 15 秒续租；多实例通过 Redis WATCH/MULTI 竞争，只有当前持有者可以更新状态。新实例在启动和轮询中恢复过期租约。

- 保留原任务 ID、原始截止时间；恢复最多 3 次执行，不重新给 30 分钟。
- 成功模型输出按请求指纹保存，重启时匹配的调用直接复用。已发给供应商但未返回的调用无法在本地续接，可能重做；不声称供应商调用恰好执行一次。
- Redis 不可用时不确认任务入队，不退化成不可恢复的内存执行。
- 跨实例取消写入持久化终态；旧执行者失去所有权后不能覆盖结果。
- 进度及产物回传前校验执行所有权。更新失败时保留任务用于受限恢复。
- 依赖现有的预留实例及 `alwaysAllocateCPU`。此变更没有把常驻 worker 宣称为 FC 托管异步调用；未来改变算力模式时必须同步迁移消费者。

阿里云说明，HTTP 返回后普通后台协程不具备完成保证；该平台行为与当前进程内设计不匹配。[FC 异步代码说明](https://www.alibabacloud.com/help/doc-detail/2384606.html)

### 发布保护

发布同时检查 SQL 的 queued/running 任务、BullMQ 队列和正在受理的请求。维护入口与请求登记是原子的；正在生成的用户工作会阻止发布替换实例。第一次升级也通过管理员任务 API 独立核对 SQL 数量，兼容旧的错误排空接口。查询失败即停止发布。回滚使用相同检查。

### 模型及日志

- DeepSeek V4 官方接口默认开启思考模式；对于当前受输出长度约束的 JSON/HTML 流程，显式配置非思考输出模式，避免隐式思考预算消耗正文空间。仅向官方 DeepSeek V4 接口发送专属字段，其他供应商不变。保留配置开关。
- DeepSeek 配置依据：[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[Chat Completions 参数](https://api-docs.deepseek.com/api/create-chat-completion/)。
- 修复模型调用日志、活动记录缺少 FC 内部认证头的问题；检查 HTTP 返回状态，回传被拒绝时记录警告。
- 预检查失败事件写入具体问题、失败原因和失败类别，不再只写“重新生成”。
- Provider 新建界面、服务默认值和数据库默认值统一 1800 秒。已有 Provider 的单独配置需要在发布验收中核对；数据库迁移不擅自覆盖已有行。

### 桌面互动作品

用户从创作主页提交的明确“桌面浏览器可交互创意作品”请求，进入独立的 `interactive_experience` 路径；迭代通过保存的作品类型保持该模式。

该路径直接遵循原始创意，移除由旧意图解析推断的答题、得分、生命值和输赢约束。模型输出仍须通过真实 Chromium 校验：完整 HTML、可读说明、可用控件、内容随交互变化、无脚本错误、1366×768 和 1920×1080 无横向溢出。未执行或未通过浏览器校验，不可发布。游戏路径原有质量门槛继续保留。

浏览器校验是交互和布局检查，不等价于科学正确性证明。科学作品仍需按具体公式、单位、参数和预期趋势进行业务验收。

### 真实验收补充：动画启动检查

版本 `07b4edb` 发布后，真实创建任务 `baebd65c-ca3b-4902-a0b0-62577d62111f` 成功。迭代任务 `a5e41086-35bf-461d-9120-b72b350b33bb` 虽返回成功，业务浏览器检查发现“开始”不能推进模拟：生成代码对每帧约 16 ms 的时间除以 50 ms 后取整，始终得到零步。

旧的桌面自动检查只要求任一控件改变页面，滑块数字变化掩盖了这个问题。补充规则：存在动画帧或周期计时器时，逐个启动控件检查点击完成之后内容是否继续变化；停止的动画必须触发 QA 修复，不能凭按钮文字或滑块数值变化通过。纯静态“开始探索”动作不被要求持续动画。生成约束同时强调固定步长必须累计时间余量。
