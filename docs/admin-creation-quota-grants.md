# 管理员追加创作额度

后台“额度与套餐授予”中，搜索并选择目标账号，填写授予原因和追加次数，点击
“确认追加额度”。单次支持 1–10000 的整数次数；确认框显示目标账号、数量和原因。

追加次数立即生效、长期有效。它增加现有基础及赠送余额的累计额度，不清零已用次数，
不修改会员状态、套餐、到期日或付费订单。已有有效套餐但额度耗尽的账号也能追加。
创作页刷新即可读取新余额；继续使用既有创作扣减和生成失败返还逻辑。

## 接口

- `GET /admin/quota/grants?userId=<用户编号>`：读取可用余额及最近 50 条授予记录。
  不提供用户编号时只返回最近的授予记录。
- `POST /admin/quota/grants`：追加额度，JSON 字段为 `requestId`（UUID）、`userId`、
  `amount`（整数）、`reason`（1–255 字）。两条接口均校验既有管理员会话。
- 新用户没有额度记录时，按照现有 `BILLING_DEFAULT_FREE_QUOTA`、
  `billing.default_free_quota`、默认 5 次的顺序初始化，再追加指定次数。

相同请求编号和相同内容重复提交，返回原记录；编号相同而内容不同返回冲突。
余额变更与独立审计记录在同一事务提交，审计失败则回滚。账户锁、额度行锁和原子增量
防止并发覆盖，数据库并发冲突有界重试。审计保留累计额度变化、授予时已用次数、原因与操作员。

管理页面保存未确认请求的编号。网络中断或刷新后，选择相同账号并保留相同次数和原因
重试，不会重复发放。收到成功结果后清空次数，下一次追加需要重新输入并确认。

## 验证

服务与后台交互测试覆盖耗尽套餐、重复/不同内容请求、输入边界、权限、余额溢出、
新账号默认额度、双击、刷新重试和读取失败时禁用授予。CI 的隔离 MySQL 验收进一步
检查真实并发追加、同请求去重、账单额度查询和审计故障回滚；不连接生产数据库。
