# LLM 网关三模块重构与验证记录

日期：2026-09-09。状态：本地实现和回归；未提交、未部署、未迁移生产数据库。本文替代此前的“统一主模型 + 备用服务”方案。

## 已实施的产品结构

1. **Provider 配置**：只管理名称、API 地址、Key、协议和启用状态。区域与超时放入高级项；不再要求填写模型。空 Key 保留旧值，接口不返回明文 Key。
2. **Model 配置与测试**：一个 Provider 可以有多个独立模型记录，包含模型 ID、显示名、启用状态，以及可选的上下文/输出上限。每个模型独立测试，使用已保存的确切模型，不隐式切换快模型。未声明的能力保持未知，不自动写成 false。
3. **业务环节配置**：仅保留作品生成、作品修改、辅助处理。每个环节选择主模型及可选备用模型；主备可以属于同一个 Provider，但不能是同一条模型记录。

旧的逐 stepKey 编辑页面、Provider 内模型表单和重复测试入口已移除。旧路由 API 暂留兼容；此前未发布的 simple-binding API 已删除，不再增加第四种配置入口。

## 内部逻辑同步调整

| 业务环节 | 统一管理的内部步骤 |
| --- | --- |
| 作品生成 | code_generate.full、quality_gate.patch_fix、qa_fix.syntax_structural |
| 作品修改 | iterate.classify、iterate.param_adjust、iterate.element_change、iterate.mechanic_change |
| 辅助处理 | intent_parse、creative_anchors、code_review |

映射只有一份服务端定义，保存为绑定的 stepKeys；Python 网关直接读取，支持步骤的点号子路径。前端不维护另一套映射。

- 独立模型表与业务绑定表分离连接、模型身份和业务路由。配置版本分别进入调用快照，物理 Provider ID 继续用于日志外键。
- 新业务绑定优先于旧路由。已绑定步骤不接受旧 modelOverride/fastModel 的隐式替换，也不自动借用其他 Provider 或环境模型。
- 显式备用模型由业务配置决定，不再被旧 Provider failover 开关或调用方旧回退标记屏蔽。重试仍受已有错误分类和预算控制；流式输出不承诺中途无损切换。
- 已知输出上限不足、明确能力限制、模型禁用、区域不一致分别记录拒绝原因。没有可用主备模型时归类为 route_configuration，生成流水线直接失败，不重复整轮生成。
- 三个环节在一个数据库事务中保存；任一失败全部回滚。模型版本和业务 revision 防止旧页面覆盖新配置。配置保存后刷新网关；刷新失败与保存失败明确分开。
- 被业务引用的模型不能直接停用，被引用的 Provider 不能直接停用/换区域；数据库外键阻止删除被引用模型。
- 编辑连接保留旧模型、快模型和能力/Token 约束，不暗中解除限制。历史能力声明暂保留为只读，不根据模型名猜能力。

## 测试交互与错误证据

测试请求不自动重发，同一模型测试去重。结果只更新对应模型卡片，保留未保存草稿、业务选择及滚动位置；配置版本或 Provider 更新时间变化后，旧测试结果失效。空回复不能算连通通过，连通成功不代表长作品生成质量通过。

上游 HTTP 错误、客户端超时和网络错误分开记录。transportEvidence 包含 UTC 时间、脱敏端点、实际 HTTP 状态、白名单响应头/上游请求 ID、响应体长度与 SHA-256。普通/流式调用覆盖；不保存错误正文摘录，不为取证强读未读取的流，不记录 Key、完整作品正文。证据进入结构化日志、调用快照和任务时间线。

历史事件中的实际 HTTPStatusError.response.status_code=504 能证明配置的上游接口返回了 504，不能据此断言其背后模型厂商是根因。增强日志没有历史回填能力，需要部署后的真实调用才会产生新证据。本轮未调用生产模型。

## 数据迁移与发布顺序

迁移：`prisma/migrations/20260909000000_llm_models_business_bindings/migration.sql`。

新增 llm_gateway_models、llm_business_bindings 两表；从旧默认模型、快模型、路由覆盖模型和 availableModels 目录导入模型，保留旧限制。**不自动创建业务绑定、不修改旧 Provider/路由**，避免迁移时擅自选择模型。业务页展示旧路由摘要，管理员明确选择三个环节并确认后才接管。

发布前需要备份并验证目标 MySQL 版本支持 JSON_TABLE（MySQL 8+）、检查待执行迁移集合及模型导入预览。顺序为数据库新增迁移 → AI engine/game-service 配套发布 → 核对导入模型 → 管理员确认业务绑定 → 小规模真实生成验收。未迁移时 AI engine 保持旧路由兼容；新管理界面会明确提示缺少迁移。

回退代码仍可读取保留的旧路由，但新旧绑定可能已经不同；回退前应核对旧模型/Provider 状态，不能宣称无条件无损回滚。不要删除新表或数据来模拟回滚。
