## 根因模型

| 层次 | 已确认的问题 | 后果与改动 |
| --- | --- | --- |
| 生成与审核协议 | 模型须在 JSON 中逐字复述源码，转义、换行、重复片段都可能使引用失败 | 本轮潮汐拾贝确实因第 4 条源码引用无效失败。改为系统签发、绑定源码 SHA 的位置编号；系统精确还原原文，拒绝未知/旧版编号和矛盾引用，不做模糊匹配 |
| 修复寻址协议 | 工具迭代同样因 search 无法唯一匹配而失败 | 审核与补丁共用版本绑定的源码引用；整批补丁先在原文定位、拒绝重叠，再原子应用，禁止前一个补丁生成的文本成为后一个补丁的匹配目标 |
| 故障恢复 | 游戏和工具/科学的审核纠错实现不同；后者把无效审核当作品缺陷 | 抽取共用审核恢复控制器：只重审同一候选一次，不消耗代码修复次数，不因审核基础设施错误重写作品 |
| 评分目标 | 最终质量总分扣除历史修复次数，每次 0.5 分 | 同一份最终代码应得到相同质量判定。历史重试仍记录成本指标，移出最终质量总分；分类阈值和运行门禁不降低，质量策略版本升至 artifact-v3 |
| 候选状态 | 工具/科学修复无游戏路径已有的回归保护 | 保存候选检查点；运行从通过变失败、已有完整性或分类分数退化时，保留旧候选和新失败证据 |
| 验收证据 | contentChanged 只证明某处变化；源码审核看不到最终像素 | 新增真实 Canvas 文字尺寸、位置、裁切和高比例重叠证据，传入分类审核；相同文字阴影/描边不当成缺陷，艺术重叠仍由语义审核判断 |
| 阶段归因 | 工具/科学路径绕过外层阶段更新 | 共用进度适配器更新外层阶段，使超时不再统一记作 spec_build |

这批改动修复的是评价、恢复和证据之间的接口，不代表所有生成质量问题已解决。
源码编号仅证明引用对应真实位置，不能证明审核结论在语义上正确。
Canvas 几何证据不等于完整视觉验收；旋转文字、DOM/SVG、艺术构图及功能语义仍有边界。

## 尚需继续解决的架构问题

- 运行检查必须从通用点击扩展到由需求定义的操作前后断言：例如交换应交换宽高，
  撤销应恢复前态；不能把模型打分或 contentChanged 当作语义正确的证明。
- 游戏评分仍有代码长度和关键词的旧代理指标；游戏迭代质量审核仍非阻塞。这些
  不应长期承担最终交付判定，但替换它们必须同时校准新口径、回放样本并保留硬性缺陷门禁。
- 首次生成、自动修复、人工反馈迭代、展示验收、公开发布须分开记账；按部署版本、
  三类作品、生成档位、失败阶段分组。不要混合版本或重复成功作品来扩大样本量。
- 账户开始有4次额度。本轮2件首次成功和1次科学作品迭代成功后剩余1次；失败退回额度。没有充值、
  调整套餐或创建额外账户。99% 的持续验收仍需要足够的真实创建额度和代表性样本。
