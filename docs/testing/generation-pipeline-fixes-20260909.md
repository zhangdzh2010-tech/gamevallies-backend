## 已定位并修复

| 工程问题 | 证据与根因 | 修复 |
|---|---|---|
| 审查输出预算被错误缩小 | `llm_client._resolve_gateway_output_limit` 在 Provider 未配置上限时，返回的第二个值是 hint 默认值而非调用方申请值。重试包装器把这个第二个值当初始预算，造成 2048 → 512；与本批审查截断日志吻合。 | 保留显式调用预算；Provider 明确设置的上限仍然生效。两条审查链路统一使用 `medium_structured` 输出类型。 |
| 普通页面验收与正式沙箱不一致 | 原 QA 使用顶层 `set_content`；正式 `WorkSandbox` 使用 `sandbox="allow-scripts"`。`prompt/confirm` 在正式页面被禁止。 | 改为真实受限 iframe；使用隔离的作品存储适配器，不向作品开放宿主存储或同源/弹窗权限。捕获被沙箱禁止的弹窗调用。 |

| 核心首屏与绘图边界漏检 | 原只测横向溢出。摆球、主控件不可见仍通过；波形 A=2 同相振幅 4m 超出固定坐标范围。 | 四种尺寸分别直接加载/隐藏后显示；1000×600 检查核心图形和控件完整性。允许有界长列表内部滚动和下方说明。对边界输入后的连续折线记录画布越界，排除分段网格和独立 Path2D。 |
| 一次局部错误导致整篇重写 | 互动作品第二轮再次调用 `code_generate.full`，把旧文档追加进提示词。 | 完整候选改为 `quality_gate.patch_fix` 精确替换 JSON；最多 12 个局部补丁，唯一匹配、原子应用，拒绝整篇替换。补丁无效保留原候选并失败，不偷偷再生成。结构截断的文档仍可完整重生成。 |
| 失败诊断缺源码 | 预检失败和非补丁质量门禁失败只附报错；审查/浏览器基础设施失败也可能丢失当前互动候选。 | 这些分支均附作者范围内的候选 HTML 与检查报告，复用现有产物通道。互动失败保留各轮候选及操作元数据。 |
| 返工成本不直观 | 任务级 `retryCount` 不等于全部生成/补丁次数。 | 互动 QA 报告增加 `fullGenerationCalls`、`patchCalls`、`qaAttempts`，区分整篇生成和定向修复。不是全平台完整计费账本。 |

生成规范同步增加：禁止原生弹窗、保留表单键盘操作、真实时间倒计时、输入按纯文本、筛选不改变总计、边界绘图留白；游戏规范增加初盘拷贝恢复、独立记录每局先手、失焦不清盘、不添加无效提示按钮。这部分是约束强化，不把提示词本身当作正确性证据。

## 重要实现细节

- 旧版 Playwright 在 `service_workers='block'` 时会向不透明 iframe 注入不安全的 `navigator.serviceWorker.register` 覆写，引发工具自身 TypeError。新检查不使用这段注入；作品依然处于不透明来源，CSP `worker-src 'none'` 和全请求拦截仍生效，没有放开网络或 iframe 权限。
- 科学绘图探针只检查连续、横向跨越大部分画布且至少 32 点的折线是否越出画布高度；分段网格与传入的 Path2D 不纳入。这不是所有 Canvas 几何错误的通用解法，角弧方向、公式/单位仍需要领域断言与独立审查。
- 重置检查针对“初始非空计算输出变为占位符”的确定性回归，不强行要求倒计时忘记用户当前选中的茶类。
- 离线回放使用已保存 HTML，数据库配置读取被测试替身禁用，不请求生产 API、模型或在线资源。

## 复核首轮证据时的更正

《林间连线》《灯火归巷》的 `failed_quality_candidate.payloadText` 实际已保存完整失败源码，首轮没有提取这部分。此前“所有失败游戏都没有候选源码”的判断不准确，已更正原报告；新增产物修复针对另外三个缺失分支，不重复实现已有功能。

进一步读源码确认：

- 《林间连线》的 `blur` 处理确实调用 `restartGame()`，会清掉正在下的棋局。
- 《灯火归巷》的 `restartCurrentLevel()` 调用 `startLevel()`，后者重新随机生成棋盘，没有恢复已有 `initialBoard`。
- 不能把所有模型审查文字当事实。例如《灯火归巷》`applyFlip` 在翻转前执行 `cloneBoard`，单靠“快速点击”不能推断历史栈两项必然相同。这类未独立复现的推断没有作为代码修复依据。

没有修改未知源码的预检判定来换取通过率。《纸间拼图》《港口分拣员》的实际被拒候选未留存，现有证据不足以判定当时是源码错误还是预检误报。
